# 自建的总拥有成本清单

> 来源：原第13章 13.20。正文未保留，自建与购买的权衡见正文第4章。

团队为了节省平台费自建队列和 Agent 调度，需要承担五类总拥有成本（Total Cost of Ownership，TCO），也就是从开发到退役期间为这套系统持续付出的全部资源成本。自建的判断不能只看一次性开发投入，还要覆盖运行期间的持续支出，因此下面先列出最容易被低估的五类持续投入，再把各项合并成三年总成本。

**开发与迁移**：实现队列、状态迁移、备份恢复和既有任务导入，并持续维护数据模式与兼容层。

**值守与运行**：建立监控和告警机制，管理容量，并安排夜间值班、故障演练和事故恢复；根据服务承诺，非工作时间也可能产生这部分成本。

**安全与合规**：维护身份、最小权限、访问令牌轮换、多租户隔离、审计和证据保留，新增工具和租户类型时还要重新测试边界。

**升级与兼容**：跟进供应商 API、模型、运行时和依赖升级，承担回归评测、灰度、回滚以及弃用接口迁移。

**替班与连续性**：把原开发者掌握的运行知识写成文档、纳入测试，并通过接手演练验证，确保开发者离职、请假或发生事故时，仍有人能恢复系统。

```text
三年总成本 = 初始开发与迁移
           + 三年平台、计算与存储
           + 三年值守、维护、安全与升级人工
           + 容量扩张投入
           + 事故、恢复与替班成本
```

上述各项都应使用同一货币和三年时间窗口；人工项先以实际工时乘团队统一费率，避免把一次性投入或事故成本重复计入。

容量成本往往呈阶跃式增长。例如，现有浏览器池还能接收一百项短任务时，边际成本主要来自增加的使用量；一旦并发超过池容量，团队可能同时需要新增运行器、监控分片和夜间值班，下一百项任务的成本就不能再按原来的平均值估算。

是否自建，要同时考虑三年总成本，以及自主控制业务流程能带来的收益。不能只比较单月订阅费的差额，还要算上值守、安全和升级的成本。通用基础设施可以买，但业务任务、评测标准和动作政策仍要由团队掌握。
