# 月度成本评审表

> 来源：原第13章 13.14。对应正文第8章 8.11 节。

周报循环减少了读取范围和人工核对量，评审时仍要确认这些改动是否真正降低了完成成本，是否遗漏项目或淡化风险。表 1 将总额、单位成本、失败原因和人工处理分开追问，供每月或扩大自动化范围前使用，避免仅凭账单下降就宣布优化成功。

表 1  月度成本评审的问题与所需证据

| 问题 | 需要的证据 |
|------|------------|
| 哪类任务花费最多？ | 按任务类型的总成本和成功量 |
| 哪类任务单位成本最高？ | 完成一项业务任务的全成本 |
| 费用花在正常执行还是重试？ | `run_id` 与失败分类 |
| 上下文中哪些内容反复加载却少被使用？ | 检索与引用记录 |
| 哪些判断可以由规则替代？ | 人工修改和验证失败类型 |
| 哪些产物无人使用？ | 打开、采用或后续动作记录 |
| 人工时间主要花在哪里？ | 审批、修错、例外与维护分类 |
| 预算耗尽时系统是否按优先级降级？ | 降级与跳过记录 |
| 最近变更怎样影响质量和成本？ | 按版本的对照指标 |

表 1 前两行需要一起看：总成本高可能来自完成的任务多，单位成本高才需要继续拆查重试、上下文和人工环节。对每周一份的周报，模型总额不高，人工二十五分钟核对却可能决定优化顺序；若项目覆盖或引用记录缺失，就还不能判断缩小输入是否划算。表中的证据要关联同一周期和版本，不能拿新版费用与旧版质量拼成结论。

评审最终应在扩大、维持、降级和退役四类决定中作出选择。若数据不足，默认维持当前版本，并指定负责人补齐缺失记录。同目录 `单任务成本账_合成示例.md` 把这些归集要求放进一份月度合成账本，检查从各项支出到成功分母的计算是否完整。
