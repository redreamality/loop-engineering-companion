# 独立验证各层的工具候选与验收证据

> 来源：原第12章 12.4。对应正文第8章 8.2 节。工具均为备选，版本与行为须在本地环境实测。

把退款控制链落到系统中，首先要找出每道检查由什么机制执行、留下什么证据。表 1 将实现选项与验收证据并列：字段校验可以拒绝结构错误，却不能确认订单归属；只读查询可以提供订单状态，却不能代替退款授权。团队应从当前缺失的控制责任选择组件，而不是购买一组工具后再推定整条链已经安全。

下表中的工具是备选方案，安全性、可靠性和合规性要靠实测确认：团队要在自己的部署环境中，使用相应账号和数据，验证越权请求是否被拒绝、网络访问是否受限、日志中的敏感信息是否被遮蔽，以及失败后状态是否正确。

表 1  独立验证各层的工具候选与失败边界

| 责任 | 可比较的实现选项 | 最小验收证据 |
|------|------------------|--------------|
| 模式定义与字段检查 | JSON Schema 配合 Ajv，并显式设置 `additionalProperties: false`；或 Pydantic 配置 `ConfigDict(extra="forbid", strict=True)` | 缺字段、类型错误和未声明字段被确定性拒绝；Pydantic 侧拒绝类型不符的输入依赖显式开启严格模式 |
| 环境真值 | 业务 API、数据库只读查询；界面任务可用 Playwright | 验证器重新读取原始状态，不依赖生成器摘要 |
| 策略门禁 | 代码规则、数据库约束、Open Policy Agent（OPA）一类通用策略引擎，或使用 Cedar 授权策略语言及其评估引擎的授权组件（`SRC-PLAT-001`） | 未批准金额、对象或动作在工具调用前被拒绝 |
| 隔离执行 | 按访问边界配置的容器、受限虚拟机或平台沙箱；独立工作树仅分开工作副本，须另配执行权限控制 | 越界文件和网络请求实际失败，并留下任务关联日志；只有独立目录不能算通过 |
| 秘密与短期身份 | 操作系统或云秘密管理服务、Vault 等选项（`SRC-PLAT-001`） | 凭证不进入提示词和产物，到期后无法继续调用 |
| 端到端观测 | 结构化运行表，或 OpenTelemetry、Jaeger 等观测选项（`SRC-PLAT-004`） | 能沿 `task_id`（稳定标识同一业务任务）连接输入版本、检查结果、审批和副作用 |

Ajv 是 JavaScript 环境中用于校验 JSON Schema 的库，Pydantic 是 Python 中用于声明数据模型并执行校验的库；二者是实现选项，具体版本、配置和运行时行为必须在项目环境中实测。这两个选项的默认行为需要特别核对。JSON Schema 没有设置 `additionalProperties: false` 时通常允许未声明属性，Pydantic v2 没有配置 `extra="forbid"` 时默认忽略额外输入；只写了字段类型，也不能声称未声明的危险字段一定被拒绝。类型是否被拒绝，两个选项的默认表现不同：JSON Schema 按声明的类型校验，Pydantic 的默认模式却会把形如 `"123"` 的字符串解析成整数，须显式开启严格模式才会拒绝类型不符的输入。即使结构严格，模式定义也只验证声明过的约束，金额是否合理、对象是否获准和内容是否符合政策仍由后续检查负责。

OPA 与 Cedar 的类别不同：OPA 是读取结构化输入并执行已定义策略的通用策略引擎；Cedar 是表达授权关系的策略语言及其评估引擎。二者执行组织已经写明的规则；业务政策由组织定义，输入事实的可靠性要另行核验。

隔离执行这一行要分清两个问题：独立工作树可以避免并行任务直接修改同一份代码，却不会自动禁止进程访问其他目录或网络。要运行不可信代码，还必须限制进程身份、文件访问、网络出口和可用凭证，并用越界请求验证这些限制。容器、虚拟机和沙箱同样取决于实际配置，不能仅凭采用了某种工具就认定隔离成立。

工具接入顺序也影响风险。先使用历史样本和测试账户，让验证链以只读方式运行，将验证结果与人工结论比较；再用一批故意构造的越权操作，检查门禁能否拒绝；最后才连接专用动作服务。任何一层无法提供可查询的证据时，循环都应只生成草稿，或由人工执行后续操作。
