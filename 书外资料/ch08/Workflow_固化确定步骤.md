# 用 Workflow 执行已经确定的步骤

> 来源：原第13章 13.3。对应正文第8章 8.9 节。产品执行与调用边界见来源说明 SRC-FB-004。

有些重复工作每次重新推理都是浪费。例如，读取一份格式固定的待办清单，按日期筛选逾期项，计算各类数量，再按固定模板保存报告。第一次可以通过对话把处理方法确定下来；以后继续让 Agent（在给定目标、上下文、工具和权限范围内选择步骤并执行任务的主体）重新阅读要求、选择工具和组织步骤，就会重复消耗模型词元。

Floatboat 的 Workflow 可以把这类已经明确的步骤保存成可执行流程，由宿主（承载并运行这个流程的环境）直接运行。**不调用模型的固定流程，执行本身不消耗模型词元。** 这与第5章定时交给 Agent 处理一个目标的 Automation 不同：Automation 保存目标与日程，仍由 Agent 处理任务；Workflow 可以直接按已写好的程序读取、筛选、计算和输出。产品执行与调用边界见来源说明 `SRC-FB-004`。

这里要分清创建与运行。请助手编写、解释或修改 Workflow 的对话会使用模型；Workflow 运行中如果再调用 Agent 判断、写作或修复，那些步骤也会消耗模型词元。调用的子流程或外部服务同样需要检查，不能只看外层名称。计算、存储、第三方接口或付费流程还可能有其他费用，因此不消耗模型词元不等于整项工作没有成本。把方法整理成 Combo 也不会自动消除随后 Agent 执行任务时的模型调用。

**直接描述要创建的流程**

已经知道处理规则时，可以在对话框输入：

> 帮我创建一个workflow，作用是：xxx。

把 `xxx` 换成具体工作。这里可以沿用第5章的待办摘要，但先只做规则明确的部分：

> 帮我创建一个workflow，作用是：读取我指定目录里的待办清单，按我传入的业务日期筛选未完成的逾期事项，按原截止日期排序，统计数量，并生成固定格式的本地报告。缺少日期的事项单列，不推测日期，不调用模型，不修改原清单，不发送消息。先说明输入、输出和处理步骤，等我确认后再创建。

这是一种自然语言交代方式，无需记住专门语法。日期、输入目录和输出目录应成为每次运行的参数，把今天的值固定写进流程会在下次运行中失效。阅读内容、判断优先级或撰写分析等仍需模型的部分，可以留在对话中处理，先不要把它们混进这条无模型调用的流程。

**从已经完成的会话整理**

还没有稳定做法时，先通过对话完成一次任务。核对文件、计算、排序和缺项处理都符合要求后，留在当前会话输入：

> 把当前对话整理成workflow。

如果复用的是以前完成的工作，先回到那段会话，确认其中的资料和方法仍然适用。让助手提取最终采用的步骤、输入参数、输出格式和失败条件，不把试错过程、临时路径、客户原文或凭据全部打包进去。涉及生成或主观判断时，先决定保留为模型步骤，还是改成确定性规则；不要为了得到零模型词元的说法，偷偷省略必要检查。

**保存后，用同一份样本比较**

先取得实际保存的 Workflow 标识或文件位置及校验结果，再在隔离的练习目录运行一次。对于上面的例子，用原来已核对的清单检查：逾期项和排序是否一致，缺日期项是否单列，原文件是否未变，报告是否确实保存。随后检查流程及其调用链是否包含 Agent 或其他模型服务调用，并核对可取得的运行记录和用量证据。没有看到词元数字只能说明缺少用量数据，不能直接记为零。

在相同输入和完成标准下，分别记录原对话方式与 Workflow 的运行次数、模型调用、工具费用和人工检查时间。只有固定处理部分真正不再调用模型，且结果仍满足标准，才能把减少的推理记为节省。流程稳定后再决定是否设置定时或事件触发；保存 Workflow 不会自动建立这些安排。
