# 破窗授权的字段与使用规则

> 来源：原第12章 12.23。对应正文第8章 8.3 节“紧急权限必须自动到期”。

在事故处置中，值班人有时需要读取平时不可见的日志、撤销大批任务或切换动作服务。紧急权限应单独设计，不能靠管理员临时把自己加入长期高权限组。

在正文第8章 8.7 节的跨客户摘要事故中，值班人需要冻结检索证据、撤销批准，并核对下载与发送记录。这些操作可能超出日常权限，但也不能因此开放全部客户资料或长期保留高权限。表 1 把事故处置所需的紧急权限（即破窗授权：事故中用于暂停、调查或恢复的紧急高权限路径）限定到具体事故和对象，使事后复核能够区分必要调查与无关访问。

表 1  破窗授权的事故、权限、人员、时限与复核

| 字段 | 含义 |
|------|------|
| 事故 | 只能用于哪个已登记事故 |
| 权限 | 允许查询、暂停、撤销或恢复哪些对象 |
| 人员 | 申请人、批准人和实际使用身份 |
| 时限 | 自动到期时间，通常按小时而非月份 |
| 记录 | 每次查询和动作的对象、时间、结果 |
| 复核 | 事故后由未参与使用的人检查必要性 |

表 1 中，事故限定用途，权限限定可以操作的对象，时限限定这种例外持续多久；人员与记录则让独立复核者能够查清谁实际做了什么。只登记事故编号而不限定对象，仍可能把局部调查扩大成全域访问；只设到期时间而不留动作记录，也无法判断权限是否被滥用。事故、权限、人员、时限、记录或复核，任何一项缺失，都不能签发破窗授权。

遇到真正危及人身、资金或大范围数据的事故，可以允许先使用权限，再在短时间内补批，但这种例外也要事先规定。紧急账号不能用于日常排障，不能共享密码，使用时仍须填写事故编号等关联字段。事故结束后，应自动撤销权限，并验证访问令牌已经失效。

恢复权限与暂停权限可以分别设置。应允许较多人员执行紧急停止，但恢复高风险操作，必须由系统与业务负责人共同确认。这样，值班人就能在暂停动作上立即行动，不必顾虑自己是否有权恢复系统。
