# 事故复盘：摘要里出现了另一位客户（完整版）

> 来源：原第12章 12.22。正文第8章 8.7 节为压缩版。本案例为教学用虚构事故。

下面是一则用于教学的虚构事故。一家咨询公司让 Agent 根据项目记录生成客户周报草稿。周二 09:12，项目经理在草稿中看到一段不属于本项目的工厂停产风险说明。这条信息涉及另一家客户，虽然没有出现客户名称，但地点和产线信息已足以让业内人员推断出是哪家客户。

这次事故并非由模型编造事实引起。检索服务在合并项目资料时，先取了用户有权访问的全部片段，再要求模型按客户过滤。一个缓存键只包含“周报”和日期，没有包含租户与项目 ID。上一项任务的检索结果因此进入了当前上下文。

**前十五分钟**

09:14，项目经理点击“报告数据问题”，系统登记了一项安全事故，并关联当前任务、草稿版本和证据片段。值班人没有先删除日志，而是按预定方案暂停相关操作：

- 09:14，运行值班人暂停所有使用同一检索服务的客户内容生成；完成证据是暂停记录和新运行数归零；
- 09:15，审批服务负责人撤销尚未发布草稿的批准；完成证据是相关 `approval_id` 全部失效；
- 09:16，动作服务负责人禁止现有任务继续调用对外发送动作；完成证据是发送门禁的拒绝日志；
- 09:17，数据值班人冻结原始任务包、检索结果、缓存元数据和访问决策；完成证据是事故证据清单与只读快照；
- 09:18，事故负责人核对邮件、下载和外部分享账本；完成证据是按动作类型汇总的确认数量与未知项。

暂停范围限于可能受影响的流程：经该检索服务读取客户资料的摘要任务全部停止，仅仅读取公开资料的摘要任务可以继续。

09:21，动作记录显示该草稿尚未发送，但同一版本已在 09:01 被项目经理下载过 PDF。该下载发生在下述 08:40 至 09:14 的影响窗口内，计入“下载 1 次”。下载属于数据离开受控界面的动作，需要进入影响调查，不能因为没有发邮件就宣布“无外泄”。

**第一小时**

调查者根据 `retrieval_run_id`（标识一次检索及其缓存命中范围），查找同一缓存键的全部命中记录和受影响任务；仅靠全文关键词搜索，无法可靠地确定影响范围。调查结果如下：

```text
受影响控制：周报检索缓存 v7
开始 / 结束时间：08:40 / 09:14
可能受影响任务：12
实际生成草稿：8
被人打开：4
下载：1
外部发送：0（由动作服务记录确认）
涉及客户：2
敏感数据类型：项目地点、运营风险、时间窗口
当前遏制：相关检索暂停，发送批准撤销，缓存隔离
```

团队分别通知数据负责人、两个客户项目负责人和安全负责人。是否需要向客户或监管方报告，由合同、数据类型、辖区和实际披露范围决定，不能让生成 Agent 按模板自行判断；本材料不替代法务意见，具体通知义务、时限和对象须由具名责任人按适用合同和法律核定。

**根因与修复**

“模型没有遵守只谈本项目的要求”停留在表面。检索服务在召回资料后才按授权过滤，访问数据前没有限定对象，因此先取到了其他项目的片段。缓存键又缺少租户、项目、权限版本和数据用途，导致当前任务复用了上一项任务的结果。验证器虽然检查事实是否有来源，却没有检查来源是否属于当前任务，因此未能拦住其他客户的资料。测试只检查用户能否直接打开无权访问的文档，没有覆盖共享检索与缓存，这个权限检查缺口因而长期未被发现。此外，下载操作没有纳入内容循环的风险检查，影响调查险些漏掉已经离开受控界面的 PDF。

修复时，在检索阶段就按租户和项目条件筛选数据，按任务授权划分缓存，并为每个片段标注所属对象和数据用途。验证器对全部来源重新进行对象级授权检查。测试中加入两个名称相似、字段重叠的客户，确认检索、摘要、缓存和日志都不会混入其他租户的数据。

恢复时，先用合成数据运行，再选择内部项目进行影子运行、生成草稿，最后只为一个客户开放草稿功能。在观察期内抽查检索来源和拒绝记录。旧任务不能从被污染的检查点继续，应使用未受污染的数据重新发起运行。

**通知里说明什么**

事故沟通要分别说明已确认的事实、仍在调查的问题和已经采取的措施。不能为了安抚而写“任何数据都没有泄露”，也不能把十二项可能受影响的任务说成十二次实际披露。

内部通知至少包含事故编号、当前影响范围、已暂停功能、员工需要停止的动作、下一次更新时间和报告渠道。对外通知由具名责任人依据合同和法规批准，保留发送版本与收件范围。
