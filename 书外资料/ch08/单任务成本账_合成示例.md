# 单任务成本账：记账字段、合成账本与模型比较

> 来源：原第13章 13.2（任务与运行分开记账）、13.15、13.16。对应正文第8章 8.8、8.9 节。所有数字均为教学用合成数据。

**任务和运行分开记账**

一项任务可能有三次运行：第一次数据源超时，第二次验证失败，第三次成功。三次运行的费用都计入同一个 `task_id`，每次运行仍保留独立 `run_id`。这样既能计算每项业务任务的成本，也能看出重试造成了多少额外开销。

前面那项第三次才成功的任务，如果账本只保存最终结果，前两次支出就会消失；如果把三次运行都计作完成，单位成本又会被低估。表 1 用任务层和运行层两组字段保留这一区别，让费用能汇总到业务结果，也能追查到具体失败。

表 1  单位成本记账的任务字段、运行字段与结果分母

| 字段 | 层级 | 用途 | 示例 |
|------|------|------|------|
| `task_type` | 任务 | 比较不同场景的经济性 | `customer_reply` |
| `task_id` | 任务 | 汇总同一业务任务的重试和分支 | `task_20260823_018` |
| `run_id` | 运行 | 区分每次执行尝试 | `run_03` |
| `model_version` / `tool_version` | 运行 | 识别升级前后的变化 | `draft-v4` / `search-v2` |
| `input_tokens` / `output_tokens` | 运行 | 统计输入和输出的模型词元用量 | `8200` / `640` |
| `tool_calls` | 运行 | 找出外部查询与失败重试 | `search:3, customer_system:1` |
| `duration_ms` / `wait_ms` | 运行与任务 | 区分执行、排队和审批等待，单位为毫秒（ms） | `42000` / `180000` |
| `validation_outcome` | 运行 | 关联成本与质量 | `rejected_policy` |
| `human_minutes` | 任务 | 纳入准备、审核和修错，单位为分钟 | `6.5` |
| `final_status` | 任务 | 只把真正完成纳入成功分母 | `resolved` |

按表 1 记账时，先以 `run_id` 收集每次调用和失败的记录，再按 `task_id` 汇总；同一任务即使运行三次，成功完成后也只能在分母中计为一项。将失败分类与版本放在运行层，还能区分费用增长来自输入变难、模型变更，还是同一工具反复超时。只保留月度总额，就无法作出这些判断。

这些字段提供归集依据，并不是完整价目表。`final_status` 仍须符合本节预先约定的成功定义，`human_minutes` 要按统一费率换算，排队等待不能混入人工工时。口径固定后，下一步才能检查哪些任务本来就不该创建，避免用更便宜的运行掩盖重复处理。也就是说，单位成本只回答“已经发生的事情花了多少”，要进一步降低支出，还要从发现层减少不该发生的工作。

## 一份完整的单任务账

下面是一份教学用合成账本：某团队每月处理 3000 封普通客户咨询。循环先分类，再检索知识、起草和验证，最后由客服抽查或审批。表 2 把模型、工具、平台和人工成本放到同一月度账本中，说明作为分母的成功任务数如何影响单位成本。其中的任务量、单价、工时和比例仅用于演示计算，不代表客服行业基线；实际评审必须采用团队自己的账单、工时和成功定义。

表 2  三千封咨询的全成本与业务完成分母

| 成本项 | 数量或时间 | 单价示意 | 月成本示意 |
|--------|------------|----------|------------|
| 分类模型 | 3000 次 | 0.01 元 | 30 元 |
| 知识检索 | 2400 次 | 0.005 元 | 12 元 |
| 起草模型 | 1800 次 | 0.08 元 | 144 元 |
| 语义验证 | 1800 次 | 0.04 元 | 72 元 |
| 重做 | 270 次 | 0.12 元 | 32.4 元 |
| 平台与日志 | 月固定与按量 | - | 380 元 |
| 人工审核 | 42 小时 | 100 元/小时 | 4200 元 |
| 异常处理与维护 | 18 小时 | 120 元/小时 | 2160 元 |

表 2 中，起草和验证的数量对应处理阶段，人工审核与异常维护则记录完成这些工作实际投入的时间，不能因为不出现在模型账单上就省略。若团队只把起草模型价格降低一半，仅首次起草一行每月就只省下 72 元（重做里的起草份额另省约 11 元）；若改善审批包后能减少十小时人工审核，节省的成本会更多。但后者是待验证的优化条件，表中并没有给出已经节省十小时的结果。

这份合成账本只能帮助确定调查重点，不能据此削减必要审核。还要注意，分类、检索和起草的数量不同，任何一行都不能直接充当成功分母。下面先对收到的咨询逐项归类，再计算每封真正解决的成本。归类时使用的是同一个月末的状态，四类互不重叠。

**正确分母**

本例把收到的 3000 封咨询按月末状态分为互不重叠的四类：600 封被固定规则判为无需处理，不计为成功解决客户问题；1500 封完成起草并最终解决客户问题；300 封完成起草后转人工调查，当期尚未解决；另有 600 封检索后因证据不足未进入起草，已转人工等待补充资料，当期同样未解决。四类合计 `600 + 1500 + 300 + 600 = 3000`，其中起草量为 `1500 + 300 = 1800`，成功分母为 1500，未解决量为 900。这些处理结果是教学算例的设定，不是实测结果。

“未起草”是处理阶段，“转人工”是处理路径，“未解决”才是完成状态，三者不能互换。1500 封已解决咨询包含经人工审核、修改或协作后在当期解决的咨询，不因有人工参与而剔除；这里不另设自动与人工协作的拆分比例。另外两类共 900 封转人工后本期均未解决，不能再计入成功分母；无需处理的 600 封也未满足本例的成功定义。所有输入在本期已发生的分类、检索、重做、人工审核和异常处理成本仍计入分子，不能因未解决而删去。

表中 2400 次检索设定为除无需处理者外每封检索一次，其中 600 封检索后转人工、1800 封进入首次起草与验证。270 次重做是这些任务中的额外处理次数，不是新增 270 封输入，也不额外增加成功量；其起草与验证费用合并列在“重做”项，不再重复计入首次起草与验证行。

```text
每封成功解决成本 = 总模型、工具、平台与人工成本 / 1500
```

表 2 的月度总成本为 `30 + 12 + 144 + 72 + 32.4 + 380 + 4200 + 2160 = 7030.4 元`；按 1500 封成功解决的咨询计算，单位成本为 `7030.4 ÷ 1500 ≈ 4.69 元/封`，结果四舍五入到分。还可以把“未解决转交”的 900 封单独算一笔成本，看它们消耗了多少检索、人工审核和异常处理；团队若能取到自动放行与人工协作的完整记录，也可以再按这两条路径细分已解决的 1500 封。只看一个平均值，容易忽略某些咨询意图的处理成本特别高。

## 便宜模型为什么可能更贵

前面的合成账本按处理环节分列了成本，但起草环节只是其中单独一行，换用不同模型会怎样改变重做和人工成本，账本本身还回答不了。真正要决定用哪个模型起草，还得看这一环节本身的单价与代价如何互相抵消。

这里的模型比较使用教学用示例数据，用于说明低调用价格怎样被重试和人工成本抵消；这些比例、时长和价格不是模型能力或客服行业基线，实际选择必须在同一任务集和本地人工成本口径下重测。下面先算一笔人工账，再看表中的整体对比。

团队试着将起草环节换成价格低 60% 的模型。模型调用费用下降了，但格式错误率从 2% 上升到 9%，需要修改事实的比例从 7% 上升到 15%，平均人工修改时间增加了 18 秒。

假设 1800 封进入起草的草稿全部由人审核或修改：

```text
新增人工修改时间 = 1800 × 18 秒
                 = 32400 秒
                 = 9 小时
```

九小时的人工成本可能远高于模型调用节省的费用：按表 2 中人工审核的 100 元/小时费率，新增九小时人工修改约合 900 元；而起草单价降低 60%，首次起草部分省下的模型费用只有 `1800 × 0.08 元 × 60% ≈ 86 元`。因格式问题而重做的次数增加，还会带来额外的验证和工具调用成本，并延长处理时间。

前述九小时只是新增人工时间，还没有包括额外重试与验证，也没有回答严重错误是否仍在可接受范围内。表 3 将这些结果与调用价格并列，防止把一个环节省下的费用当成整项任务的收益。

表 3  模型比较的价格、成功率、重试与人工成本

| 指标 | 模型 A | 模型 B |
|------|--------|--------|
| 单次调用 | 高 | 低 |
| 一次通过率 | 94% | 83% |
| 严重事实错误 | 0.4% | 1.2% |
| 平均人工修改 | 24 秒 | 42 秒 |
| 重试与升级 | 低 | 高 |
| 每成功任务全成本 | 计算后比较 | 计算后比较 |

表 3 中，一次通过率指首次生成即通过自动验证、无需重做的比例；需要人工事后修改事实的草稿不计入失败。模型 B 的低调用价伴随着较低的一次通过率和较长的人工修改时间。费用从起草环节转移到了重做与人工，并没有自动消失；严重事实错误的变化还需要单独判断，不能折进平均成本后忽略。两种模型必须处理同一组任务，采用相同的成功定义和人工费率，比较才有意义。

表中最后一行有意留待计算：没有实际调用量、重试费用和完整人工记录，不能直接断言哪种模型更便宜。即使全成本较低，高风险错误也必须满足质量门槛。若差异主要集中在少数复杂任务，可以继续评测下面的混合路由，而不必一次替换所有起草任务。

**混合路由**

团队最终可能用低成本模型处理格式稳定、事实字段明确的常见问答；发现多个意图、相互冲突的资料或高风险信号时，再升级模型。路由器本身也要评测，尤其要检查是否把复杂任务误判为简单任务，导致没有按要求升级。混合路由把前面表中的分层落到一条具体规则上，因此还需要在运行记录中保留每次的路由依据，便于事后核对升级是否发生在正确的时机。
