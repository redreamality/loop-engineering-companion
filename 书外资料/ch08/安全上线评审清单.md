# 安全上线评审清单

> 来源：原第12章 12.15。对应正文第8章 8.3 节。

在上线或扩大自动动作的范围之前，团队应逐项评审以下问题：

**范围与身份**

- 任务是否有稳定业务身份，重复和乱序怎样处理？
- 哪些输入属于外部不可信内容？
- 每项关键事实以哪个数据源为准？

**权限与动作**

- Agent 能读取和修改哪些具体资源？
- 权限是否短期、可撤销并绑定任务？
- 哪些动作不可逆或影响范围大，谁批准？
- 怎样保证外部动作幂等，怎样发现只有部分操作成功的情况？

**验证与人员**

- 成功标准是否在执行前确定并版本化？
- 哪些检查由代码、模型和人分别承担？
- 审批人是否看见原始证据和拟执行差异？
- 审批队列超过容量时，系统怎样降速？

**运行与恢复**

- 单次和周期预算、并发、重试上限是什么？
- 哪些条件触发暂停，谁有权恢复？
- 中断后从哪个状态继续，哪些动作需先确认？
- 能否沿任务 ID 还原版本、权限、证据和副作用？

**学习与变更**

- 人工修改是先作为反馈记录下来、继续观察，还是直接变成规则？
- 偏好、事实、Skill 和政策由谁批准，作用域是什么？
- 模型、数据源或规则升级怎样评测、灰度和回滚？

关键问题还没有答案时，循环应只生成草稿，或继续由人工执行后续操作。流程已经搭建完成，并不代表风险已经解决。
