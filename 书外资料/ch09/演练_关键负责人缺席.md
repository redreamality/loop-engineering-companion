# 演练：关键负责人同时缺席

> 来源：原第15章 15.24 节。对应正文第9章 9.8 节（四类负责人与决策权）与 9.13 节（人员变化）。

许多运行手册都默认业务负责人和系统负责人随时能联系上。团队应在非生产环境中，演练两人同时休假或无法联系的情况，并逐项保存可核对的结果：

1. 指定接收严重告警的替班人，用演练记录确认他能识别影响范围，并按规则升级处理。
2. 验证替班人能否在限定时效内取得最小必要权限，并记录签发、使用和回收。
3. 列出必须停止的动作和可按低风险政策继续的动作，分别绑定政策版本和负责人。
4. 指定能够代表业务向客户或员工沟通的授权人，并准备内部通知路径与审批记录。
5. 确认恢复是否需要原负责人，或预先配置有权限的替代审批路径和生效条件。
6. 检查交班后怎样收回临时权限、移交任务和仍待决定的事项，并保存核对结果与责任确认记录。

每次演练都要保存演练 ID、时间、参与者、模拟故障、六项检查结果、实际操作证据、未通过项、修复负责人、截止日期和暂停范围。严重告警无人接收时，暂停受影响的循环；替班权限无法按时签发时，保持人工流程；无法说清哪些操作应停止时，先停止全部外部动作；无人获准对外沟通时，只保留内部通知；恢复运行仍依赖原负责人时，补充对替代人员的授权，并继续按降级方式运行；临时权限尚未收回，或未决任务尚未交接清楚时，不得结束演练。修复完成后，应由搭建者以外的人员重新演练相应步骤，核验证据通过后，才恢复原来的运行范围。

演练中若每个问题的答案都是"找搭建者"，就说明这条循环还不能由组织内的其他人接手。替班人要能查看任务状态、核对证据、暂停会产生副作用的操作，并转入人工流程，理解每段提示词不属于交接要求。
