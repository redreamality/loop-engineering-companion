# 跨部门交接包

> 来源：原第15章 15.6 节。对应正文第9章 9.10 节（跨部门交接：合同启动循环）。

跨部门交接使用结构化任务包，而不是一段自由文本。以"销售 → 交付"的合同启动交接为例：

```text
业务对象：客户项目 ID
交接类型：销售 → 交付
已确认事实：合同版本、范围、金额、关键日期
未解决项：客户数据访问方式待确认
批准记录：签署、财务、业务负责人
下游允许动作：创建项目草稿，不通知客户
完成标准：项目负责人接受并确认缺失项
```

交接包还要列出缺失的信息和禁止执行的动作。下游不能因为收到了任务，就认定所有前置条件已经满足。

上游负责提供完整且注明版本的事实；下游负责确认接收，并报告无法处理的事项。接口发生变化时，双方共同评测。不能让下游用模型猜测上游字段的含义，也不能让上游只交付一段自由文本就算完成正式交接。

第一版交接的授权边界见正文 9.10 节：只建项目草稿，不通知客户，也不触发资金动作；建项与通知是两个独立动作，状态分别记录。
