# 连接评审卡

> 来源：原第14章 14.18 节。对应正文第9章 9.7 节。

新建连接，或变更事件、权限、写入入口和恢复规则之前，由连接负责人召集上下游业务负责人、共享资源负责人和动作服务负责人，共同填写下面的评审卡。它是检查模板，不是可执行配置。业务对象与权威写入口应对照领域台账填写，事件版本和任务关联应对照连接合同确认，资源使用和失败情况应有运行记录支持，动作门禁和回滚安排则由实际拥有相关权限的人确认。

```text
上游循环 / 下游循环：
业务对象与事件版本：
权威写入口：
下游读取还是允许写入：
依赖类型：强 / 范围 / 风格 / 参考 / 观测
重复、乱序和撤回：
等待状态、截止和死锁检测：
共享资源与优先级：
统一外部动作门禁：
上游暂停时下游怎样降级：
连接变更的影子、灰度与回滚：
端到端业务指标和任务关联字段：
```

连接投入生产前，必须确认权威写入口唯一、读写权限明确，能够处理重复事件、乱序和撤回，任务等待或失败时也有明确的后续处理办法。统一动作门禁、灰度发布和回滚，都要经过实际验证。任何一项尚未满足，就继续采用人工交接或影子运行：对象身份不清，先对照领域台账补齐；资源限制或动作门禁不明，先暂停写入；缺少恢复证据，先做混沌演练（见本目录《多循环混沌演练.md》）。不能只因正常路径跑通，就批准上线。
