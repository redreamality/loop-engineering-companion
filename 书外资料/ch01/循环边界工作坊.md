# 循环边界工作坊（《循环工程》第 1 章配套）

> 来源：第 1 章（原“循环边界工作坊”）。选一项目前由人反复完成的任务，用一次团队工作坊明确系统、Agent 与人各自负责的部分。

在白板上分三栏写下：

第一栏是“系统可以直接读取的信息”，包括按固定字段记录的任务状态、已经批准的政策，以及本次任务所需的输入资料。

第二栏是“可以交给 Agent 的工作”，包括对信息进行分类和归纳、起草内容、提出备选方案。

第三栏是“必须由人或组织决定的事项”，包括对外作出承诺、批准例外、动用资金、删除数据、公开信息，以及修改规则。

然后画一条时间轴，依次标出信号出现、创建任务、执行任务、验证结果、执行对外操作和进入下一轮。在每个环节旁边注明需要哪些资料、要获得什么权限，以及需要读取或更新哪些状态。

完成后，参与者一起核对以下五个问题：

- **哪些判断可以按固定规则完成？** 对日期范围、允许的状态值、金额上限和必填字段，分别写清楚检查什么内容、依据哪些输入，以及如何确认检查通过。难以用固定规则判断的内容，应交给 Agent 或人处理，不要仅凭几个含义模糊的关键词作决定。
- **哪些信息必须在操作前重新核实？** 价格、权限、库存和任务状态都可能发生变化。要写清楚应从哪个权威来源读取这些信息，以及多久以前的数据仍可使用。如果读取失败或数据已经过期，就让任务等待补充资料，不能继续沿用旧值。
- **从哪一步开始，系统会实际发送消息或修改数据？** 找出系统第一次发送消息、添加标签、下单或删除数据的操作，写清楚由谁执行、如何用幂等键避免重复执行，以及需要留下哪些批准记录。如果无法确认操作是否成功，要先查询结果或交由人工处理，不能直接重试。
- **出现什么情况时，要缩小自动化范围或暂停运行？** 针对严重错误、连续失败、任务积压、预算消耗和资料异常等情况，分别写明何时停止操作、由谁处理，以及满足什么条件后可以恢复运行。一旦达到停止条件，就不再发起新的操作，同时保留正在处理的任务和告警记录。
- **怎样确认一项任务已经完成，以及整条循环可以停用？** 单项任务完成时，要记录业务结果，并保留发送、写入等操作的结果凭证。整条循环退役时，还要关闭触发机制、妥善处理尚未结束的任务、撤销访问凭据，并通知依赖这条循环的系统维护者和使用者（核对项见同目录《循环退役检查表》）。每项收尾工作都要有人负责，不能在还有无人处理的事项时就宣布循环退役。

回答这些问题时，团队往往会发现，有些问题出在任务说明不清，有些出在资料不全，还有些出在权限和调度安排上。
