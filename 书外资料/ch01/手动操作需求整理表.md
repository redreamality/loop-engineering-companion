# 手动操作需求整理表（《循环工程》第 1 章配套）

> 来源：第 1 章“跟着一项工作走到底”（原表 2-1）。用于把已用 AI 反复完成的手动工作，整理成交给系统执行的需求。

选择一项已经用 AI 反复完成的任务，回看最近三次的实际操作，按下面的问题逐项寻找证据，尤其要保留那些让你中途改变做法的细节。

*从手动操作中整理交给 AI 系统执行的需求*

| 问题 | 要寻找的证据 |
|------|--------------|
| 你怎样知道该开始？ | 记录什么时候、从哪里得知有事要做，并判断系统能否据此可靠地创建任务。 |
| 每次都要补什么？ | 列出需要补充的文件、历史记录、规则、相关人员身份和时间信息，注明来源与有效期。 |
| 你怎样判断不对？ | 记录判断时参考了哪些事实、样例或政策，以及由谁作出判断。 |
| 你改了什么？ | 区分改动发生在输入、提示、工具、权限还是最终结果，并保留差异。 |
| 什么时候停止？ | 写出通过标准、截止时间或预算阈值，并说明谁可以结束任务。 |
| 结果放到哪里？ | 记录草稿的存放位置、写入的业务系统或消息的发送位置，并注明版本及使用者。 |
| 下次怎样接着做？ | 说明如何根据任务标识查找状态、避免重复处理，并接着完成剩余工作。 |

填写“你改了什么”时，要结合“每次都要补什么”和“你怎样判断不对”两行，查清错误的来源：来自旧看板的错误日期，问题出在输入，要调整读取来源；输入本来正确、只是模型读错，问题出在生成，要补充生成示例或验证样本。只保留改好的草稿而不记录错误来源，两类问题就会混在一起。

三次记录只能用于提出需求和寻找重复出现的问题，还不足以证明规则已经覆盖了全部例外。整理时，可以把每次都按相同步骤完成的操作圈出来，编入工作流；需要理解内容的步骤，交给 Agent；资料来源不明、判断依据说不清或涉及风险决策的情况，先留给人工处理。不能把某一次的临时补救措施直接写成自动执行的规则。
