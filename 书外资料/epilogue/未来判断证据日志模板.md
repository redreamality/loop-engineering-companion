# 未来判断的证据日志

> 原第17章 17.25 节，2026-11 改版外移至配套资料。

团队会不断听到“下个季度就能全自动”“这个职业会消失”“多 Agent 将解决复杂项目”。可以把这些判断记录成带日期的假设，定期检验，而不是仅凭口号行动。

先区分三类判断，再记录各自需要的证据：

1. **当前事实**：记录一手来源、日期、版本与适用范围。
2. **趋势推断**：列出连续信号、反例与复核日期。
3. **情景假设**：写明触发条件，以及假设不成立时仍要做什么。

用来支持改变权限或流程的判断，都要在自己的数据、权限和故障场景中实测。证据不足以支持改变权限或流程时，保持草稿或影子运行；证据充分时，才进入限定范围灰度，并设置停止与回滚条件。无论是否放行，都应到期复核并更新证据日志。

不同类别的判断，需要采用不同的表述，也支持不同范围的行动。官方文档可以证明某个入口存在；它在你的数据、权限和负载条件下是否可靠，要靠本地验证；本地验证通过后，执行会产生高风险副作用的动作仍需另行获准。

下面这份记录模板只是格式示例，不是可执行代码：

```text
判断：两年后出现的长任务模型，会把合同字段提取的人工修改率降到 5% 以下
日期与信息来源：
适用范围：三种标准合同模板，不含非标准条款
若为真，我们会做什么：把人工改为例外审阅
若为假，我们仍要做什么：维护权威字段和评测
可观察信号：历史样本、影子运行、严重错误
复核日期：
```

判断可能出错，但如果预测没有注明范围、日期和可观察的信号，就很难指导投资，也容易在事后被重新解释。证据日志可以帮助作者、管理者和采购人员区分当前产品能力、合理推断与营销语言。
