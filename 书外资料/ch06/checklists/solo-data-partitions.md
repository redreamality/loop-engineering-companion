# 一人公司的数据分区（表 8-7）

> 《循环工程》配套资料（ch06 业务场景循环）。来源：原第 8 章 8.19 节；数据分区与身份分层由新版第 8 章覆盖，表 8-7 在此保留。表格沿用原书编号。

## 8.19 一人公司的数据分区

顾言的客户合同、原始照片和公开作品可能都在同一台电脑上，但内容循环只需其中已获许可的材料。如果顾言以“电脑归我所有”为由，向 Agent 授予整个目录的访问权，前面逐项目确认公开许可的做法就无法落实。表 8-7 按数据用途划定访问范围，并把读取资料与批准动作分开。

**表 8-7  一人公司的数据分区、身份与可访问范围**

| 分区 | 内容与事实来源 | 默认 Agent 权限 | 越界结果 |
|------|----------------|-----------------|----------|
| 公共 | 官网、公开作品、公开价目 | 可读取；发布动作仍需审批。 | 未获批准的发布请求停在草稿。 |
| 业务 | 客户、项目、合同摘要 | 按项目只读或写入草稿。 | 跨项目读取被拒绝并记录审计事件。 |
| 财务 | 银行、发票、税务记录 | 只做确定性查询；金额动作转人工。 | 邮件或模型不能直接改金额或结清状态。 |
| 创作原始 | 照片、视频、源文件 | 仅指定项目和目录；默认禁止上传。 | 未授权目录访问被阻断并告警。 |
| 私人 | 个人日历、家庭与健康资料 | 与业务循环隔离，不授予日常 Agent。 | 业务任务无法读取私人数据。 |
| 管理 | 凭证、策略、Skill 与连接器配置 | 日常 Agent 不可访问，仅维护时使用。 | 配置修改需管理身份和一次性授权。 |

专用工作区、账号和文件夹可以减少误读，但还要检查实际授予的权限。顾言让内容 Agent 整理公开作品时，不应同时交出财务、私人资料或管理配置的访问权；维护连接器时使用的管理身份，也不能随日常内容任务一并授予。

读表时要同时看“内容”和“默认权限”，不能因为文件容易取得就授予访问权限。例如，内容 Agent 能读取公开作品，不代表它可以进入“创作原始”区挑选客户照片；访问时仍要限定项目和目录，并取得明确许可。财务区即使只涉及一个金额，也不能因为数据量小，就允许草稿身份改写。这种区分同样适用于配套清单“业务连续性与灾难恢复”的应急接手：恢复关键业务所需的有限访问，不应变成向应急联系人开放全部资料。
