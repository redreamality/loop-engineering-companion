# 编码工具逐款详细说明：Codex / Claude Code / Cursor

> 来源：《循环工程》原第 11 章 11.8 三款产品小节，2026-11-07 缩编改写时外移；正文要点见新第 7 章 7.11。核对日期：Codex、Claude Code 为 2026-08-23，Cursor 为 2026-11-01。平台、套餐和命令会变化，使用前应按官方文档核对。

## Codex：非交互执行、沙箱与定时入口

Codex CLI 提供 `codex exec` 非交互运行，可用于脚本与 CI，并能输出逐行 JSON（JSON Lines，JSONL）事件、使用 JSON 模式定义（Schema）约束结果或保存最终消息。这里的命令名用于说明能力类别；实际运行前要安装并固定 CLI 版本，配置允许的工作区、网络和凭证，并在隔离仓库中检查退出码与副作用。`resume` 用于继续已有会话；崩溃后的自动恢复，以及发送、提交等业务动作的幂等保证，需要另行设计。

Codex 的沙箱和审批承担不同职责：沙箱限制命令能够访问的文件和网络，审批决定何时需要征求人的同意。只读、工作区可写和完整访问具有完全不同的影响范围。无人值守任务应在满足工作需要的前提下，尽量缩小沙箱的访问范围；工作区可写仍可能允许修改构建脚本、配置和仓库内的密钥引用，并非绝对安全。

Codex 还提供桌面定时任务和 GitHub Action 等入口。定时触发不会自动获得网络、工作区外写入或生产凭证。具体命令、平台和运行条件会随产品版本变化，使用前应以官方文档和本地权限配置为准；来源和主张边界见 `SRC-PROD-001`。

## Claude Code：会话循环与持久调度明确分开

Claude Code 可通过 `claude -p` 或 Agent SDK（供程序调用 Agent 的软件开发工具包）非交互运行，返回退出码与 JSON、流式 JSON 或符合指定模式定义的结构化结果。这里的命令名同样用于能力分类；真实运行需安装并固定客户端和 SDK 版本，显式提供项目依赖，并先在隔离仓库中验证退出码、文件改动和网络访问。需要跨机器一致性时，官方提供的 bare mode（最小自动发现模式）会跳过本机自动发现的钩子（hooks）、Skill、插件（plugins）、模型上下文协议（Model Context Protocol，MCP）服务、自动记忆（auto memory）和项目说明，要求调用方显式传入依赖。MCP 连接模型或 Agent 与工具和资源，业务授权仍由具体服务和控制面承担。bare mode 提高可复现性，不代表能力更强。

Claude Code 官方把几类循环分开：`/loop` 在当前会话中按间隔重复提示，`/goal` 持续工作到可验证条件成立；云端 Routines、Desktop 定时任务和 GitHub Actions 承担不同的持久运行。`/loop` 依赖会话运行且空闲，没有 cron（按计划时间触发的调度器）那样的硬实时保证，会话关闭后随之停止。云端任务从新环境开始，本机文件和配置要显式提供。相关来源见 `SRC-PROD-002`；具体时限和平台条件以部署时文档为准。

API 层自动重试只处理模型服务请求。要让 Agent 在一次运行中执行的消息发送、代码提交或其他工具副作用只发生一次，业务动作需要独立状态和幂等设计。

## Cursor：默认只提议改动，`--force` 才直接应用

Cursor CLI 可用 `agent -p` 的打印模式（print mode）接入脚本与 CI，并支持文本、JSON 和流式 JSON 输出。这里的命令名只用于能力分类；实际运行需安装并固定客户端版本、准备隔离仓库和受限凭证。按官方文档（2026 年 11 月 1 日核对），默认只提出改动建议；`--force`（别名 `--yolo`）在参数表中的定义是“强制允许命令，除非被显式拒绝”，而打印模式本身可访问包括写入和 shell 在内的全部工具，Headless 指南只是以脚本中直接修改文件为例。也就是说，`--force` 放行的不只是文件写入，还包括未被显式拒绝的命令执行；不加 `--force` 也不等于操作系统级的只读运行。无论是否启用，改动都不代表已经通过测试和独立评审。

Cursor CLI 权限可以分别限定 Shell 命令、文件读取、文件写入、网页域名和 MCP 工具，拒绝规则优先。宽泛允许 `Shell(git)`、`WebFetch(*)` 或所有 MCP 工具仍会扩大攻击面；需要虚拟机级隔离时，要另外使用隔离环境。

Cursor 主要通过 Cloud Agents 和 Automations 支持持久运行：由 cron 或 GitHub、GitLab、Slack、Webhook、Linear 等事件触发，在隔离虚拟机（VM）中克隆仓库、执行任务，并通过分支或 PR 交付。即使使用隔离虚拟机，仍要管理密钥等机密凭证（secrets）、网络、MCP 和私网连接。持久记忆（memory）在积累经验的同时，也可能保存由不可信输入引入的错误判断或恶意内容，因此不能直接作为权威知识库。相关来源见 `SRC-PROD-003`；具体时限和平台条件以部署时文档为准。
