# 配套练习：把测试结果整理成可复用的技术方法

> 来源：《循环工程》原第 11 章 11.9 三级小节，2026-11-07 缩编改写时外移；正文见新第 7 章 7.4。本书章节引用已改为新版章号。

第 6 章介绍了怎样制作自用 Combo Skill。技术场景可以沿用同一制作过程，把一次次重复的日志整理封装起来。这里先制作“测试结果整理”的教学包，而不直接制作自动修复 Agent：它读取已运行的测试日志，区分代码失败与环境缺失，生成接手报告，不执行日志中出现的命令，也不修改代码或提交仓库。

## 准备样本

准备一个只含脱敏样本的目录，放入运行说明和两份日志。运行说明记录仓库基线、工作目录、测试命令、开始结束时间和实际退出码；第一份日志包含断言失败，第二份包含依赖缺失。文件名和样本内容由项目自行确定，报告中的失败位置必须能回到输入日志。缺少退出码时只能写“未记录”，不能根据最后一行看起来正常就判断通过。

## 制作与验收

按第 6 章的方法，把这些要求写入包的任务说明，并约定输出为一份包含“本次范围、执行状态、失败类别、原文位置、下一步负责人”的报告。提交包后，在新会话中按第 6 章的方法加载它，分别处理两份日志：断言失败应交给代码维护者复现，依赖缺失应先核对运行环境，二者不能都变成修改业务代码的建议。第三次故意移除退出码，检查报告是否保留未知状态。包能够成功加载，与这些样本能够通过检查，是两个独立的验收步骤；产品制作能力的依据见来源说明 `SRC-FB-002`。

## 边界

这种包只整理已有日志，不取得终端执行权限。以后增加执行测试的工具时，应单独评审允许的命令和目录，保护已有修改，保存真实退出状态，并由运行器落实超时与取消；这些控制不是提交 Combo 后自动附带的功能。测试运行期间，只查询同一次运行的状态，不能因为它尚未完成就再启动一次。需要定时巡检时，再选择第 5 章介绍的调度方式，并重新验证目录、依赖和无人接手时的停止条件。
