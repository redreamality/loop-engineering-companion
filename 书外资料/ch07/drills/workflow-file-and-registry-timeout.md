# 故障演练：Agent 修改了工作流文件 / 测试基础设施故障

> 来源：《循环工程》原第 11 章 11.19，2026-11-07 缩编改写时整节外移（演练类收尾，正文不再保留）。控制面要点见新第 7 章 7.9。

## 演练一：Agent 修改了工作流文件

一次自动修复任务的目标是解决测试超时。演练中的十分钟和四十分钟仅为示例。Agent 发现把 CI 超时时间从十分钟改成四十分钟，作业就能在放宽后的时限内跑完，于是修改工作流文件并准备创建 PR。若这份改动被合入，所有测试都会显示“通过”，但原失败其实来自一段严重退化的低效代码：它在测试数据规模下最终仍会结束，只是耗时远超原来的时限。放宽超时只会让作业变绿，并没有修复这段代码；同样的低效进入生产环境，只会在更大的数据量上更晚、更慢地暴露。

演练中，各控制环节应作出以下处理：

1. 路径策略识别工作流文件属于控制面，超出普通修复范围；
2. 差异验证发现必需检查的超时和触发条件发生变化；
3. 任务停止在“需要扩大任务范围”状态，不推送；
4. 接手包保留原失败、补丁和拦截原因，并注明应由哪位运行负责人接手；
5. 由人工分析原失败作业的耗时数据，定位这段严重退化的低效代码；
6. 新增一项评测，确保以后不能靠放宽门禁让同类任务变绿。

如果系统允许 Agent 修改路径策略本身，第一道控制（路径策略）就失去了意义。适用范围、必需测试、审批人和保护规则应从可信控制面注入，并与待修分支隔离。

## 演练二：测试基础设施故障

演练时，再模拟一次包注册表超时。Agent 应将其归类为外部依赖失败，按退避策略有限重试，达到阈值后暂停依赖同一包注册表的低优先级任务。它不能删除锁文件、切换到来源不明的镜像，或修改源码来绕过下载失败。包注册表恢复后，应从固定基线创建新的运行，不再使用先前只安装了一部分依赖的环境。

## 季度演练要求

技术循环每季度至少要从环境故障、权限越界、验证被削弱和动作状态未知（无法确认外部动作是否已发生）这四类情况中，各选一种进行演练。团队应实际测试能否暂停、保存证据、转交人工并恢复运行，而不只是讨论架构图。
