# 任务表与运行表完整字段合同

> 编号说明：本文件由原第 6 章外移，保留原稿表号与小节号（表 6-x 对应新版正文表 5-x；6.x 对应新版 5.x）。

**任务表**一行代表一项业务任务。今天的摘要可能先因缺资料停止，补齐后才生成；无论经历几次尝试，“今天这份摘要”的身份都应保持一致。表 6-3 用一行保存其当前业务阶段，并把当前输入、产物、验证与批准关联起来。
**表 6-3  每日待办循环任务表字段合同**

| 字段 | 类型/必填 | 语义与来源 | 写入者与不变式 | 示例 |
|------|-----------|------------|----------------|------|
| `task_id` | 字符串/必填 | 由用户、业务日期和任务类型组成的业务身份；本章单用户示例省略用户段 | 控制面创建后不可改；同一业务日唯一，规则升级不新建任务 | `daily-plan:2026-08-14` |
| `business_date` | `YYYY-MM-DD`/必填 | 调度系统按 `Asia/Vladivostok` 计算的业务日期 | 创建时冻结；不得用服务器本地日期覆盖 | `2026-08-14` |
| `status` | 枚举/必填 | 业务任务当前阶段，如 `discovered`、`awaiting_review`、`completed` | 控制面按状态机更新；非法转移必须拒绝 | `awaiting_review` |
| `rule_version` | 字符串/必填 | 发现、筛选和排序使用的规则版本 | 创建任务时绑定，不参与构成 `task_id`；规则升级时在同一任务下改用新版本重新运行并记录版本变化，旧运行记录不改写 | `v1` |
| `current_run_id` | 字符串或空/选填 | 当前活动或最近一次运行的引用 | 领取事务更新；必须引用同一 `task_id` 的运行 | `run-002` |
| `input_hash` | 64 个字符的十六进制字符串或空/选填 | 最小骨架中，读取成功为输入字节的内容哈希，读取失败为错误摘要的失败指纹；均使用 SHA-256 | 领取事务写入；新运行重算；非空只说明已记录哈希，来源快照需另行保存 | `4f2c...9a10` |
| `output_link` | 统一资源标识符（Uniform Resource Identifier，URI）或空/选填 | 当前待审或已批准产物的位置 | 保存产物后写入；批准版本必须与链接哈希一致 | `artifacts/run-002-draft.json` |
| `artifact_version` / `artifact_hash` | 字符串或空/选填 | 当前产物版本及其 SHA-256 | 保存产物后成对写入；审批必须同时匹配 | `run-002:draft:v1` / `7a3d...e921` |
| `last_validation_json` | 对象序列化文本或空/选填 | 当前产物最近一次验证的状态、规则和验证器版本 | 验证节点写入；产物变化后必须重验 | `{"status":"passed"}` |
| `approver` / `approval_reason` | 字符串或空/选填 | 具名批准人及其决定理由 | 批准条件更新写入；不得由执行者代填 | `reviewer-01` / `已核对来源` |
| `approval_valid_until` / `approved_at` | 带时区时间或空/选填 | 批准有效期与实际批准时间 | 批准时写入；过期批准不得放行 | `2026-08-14T18:00:00+10:00` |
| `updated_at` | 带时区时间/必填 | 最近一次状态或证据更新的时间 | 每次条件更新时写入 | `2026-08-14T08:35:00+10:00` |

沿着表 6-3 查看一份待审摘要时，应先确认业务日期与规则版本，再从 `current_run_id` 找本次执行，从产物版本和哈希找待审文件，最后核对验证与批准。尚无产物时，相关字段应为空；填齐字段不能替代真正生成、验证或批准。任务行会随流程推进更新，上一次失败用了什么输入要到运行表中查。
**运行表**一行代表一次执行尝试。表 6-4 把这些尝试分开保存：补资料后的成功以新 `run_id` 关联到同一业务任务，之前的失败记录保留。这样才有条件核对重试是否有效，以及多次尝试累计花了多少时间和费用。
**表 6-4  每日待办循环运行表字段合同**

| 字段 | 类型/必填 | 生成时机与语义 | 写入者与保留要求 | 示例 |
|------|-----------|----------------|------------------|------|
| `run_id` | 字符串/必填 | 每次被允许的执行尝试创建一个新身份 | 控制面创建后不可改；重试不得复用 | `run-002` |
| `task_id` | 字符串/必填 | 指向本次尝试所属的业务任务 | 状态存储写入；必须满足任务表外键 | `daily-plan:2026-08-14` |
| `started_at` / `ended_at` | 带时区时间/必填/结束可空 | 记录领取与退出时间，运行中 `ended_at` 为空 | 执行器只追加结束时间；历史运行不得覆盖 | `2026-08-14T08:31:00+10:00` |
| `status` | 枚举/必填 | 本次尝试的技术结果：`running`、`succeeded` 或 `failed` | 控制面按实际退出更新；业务阶段仍看任务表 | `succeeded` |
| `input_hash` | 64 个字符的十六进制字符串或空/选填 | 与任务表口径一致：输入字节的内容哈希，或读取失败时错误摘要的失败指纹 | 创建运行时冻结；须结合读取结果区分两种证据 | `4f2c...9a10` |
| `validator_version` | 字符串或空/选填 | 检查本次产物的验证器版本 | 验证完成后写入；失败在验证前时为空 | `draft-schema:v1` |
| `validation_json` | 对象序列化文本或空/选填 | 保存通过状态、规则和验证证据 | 验证完成后写入；不得只留总分 | `{"status":"passed"}` |
| `model_cost_amount` / `platform_cost_amount` | 非负数/必填 | 本次模型与平台的可计量费用 | 运行结束汇总；未发生费用时显式记为 0 | `0` / `0.03` |
| `cost_currency` | 字符串/必填 | 费用字段使用的币种 | 创建运行时绑定；不得跨币种直接相加 | `USD` |
| `error_type` | 枚举或空/选填 | 失败时区分输入、权限、临时依赖、模式定义或未知错误 | 错误路由写入；成功运行必须为空 | `source_timeout` |
