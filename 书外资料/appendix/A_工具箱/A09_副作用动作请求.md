# A.9 副作用动作请求

> 原附录 A A.9 节外移；文中章号已按新版调整。

执行 Agent 返回候选产物，专用动作服务接收结构化请求。`operation_id` 应在请求发出前生成且唯一；业务幂等键用于识别同一业务动作，不能用一次运行的 `run_id` 代替。动作服务还应把外部系统返回的对象 ID、查询时间和最终事实写回运行记录。

```text
operation_id：
task_id / run_id：
业务对象和当前版本：
动作类型：发送 / 发布 / 付款 / 退款 / 删除 / 改价 / 其他
目标对象：
批准产物哈希：
验证结果与版本：
审批 ID、角色和时间：
政策版本：
业务幂等键：
数量 / 金额 / 速率上限：
有效期：
执行前必须重查的事实：
状态未知时的查询方式：
补偿负责人和窗口：
```

动作服务返回 `executed`、`already_executed`、`rejected` 或 `action_status_unknown`，不要只返回成功与失败。`rejected` 要记录拒绝原因和责任人，`already_executed` 要记录已存在的外部对象或事实。外部调用超时后，状态必须先进入 `action_status_unknown`，再用 `operation_id`、业务幂等键或外部对象 ID 查询事实；查询确认未执行前，禁止按普通失败直接重试副作用。
