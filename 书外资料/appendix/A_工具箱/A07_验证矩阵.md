# A.7 验证矩阵

> 原附录 A A.7 节外移；文中章号已按新版调整。

```text
产物或动作：
验证版本：

检查项 1
- 风险：
- 成功标准：
- 证据来源：
- 方法：确定性规则 / 环境测试 / 独立 Agent / 人
- 通过：
- 退回：
- 转人工：
- 系统错误：

检查项 2
- 风险：
- 成功标准：
- 证据来源：
- 方法：
- 通过 / 退回 / 转人工 / 系统错误：

放行需要满足：
任何一项失败后的状态：
验证器自身的抽样与评测：
```

检查顺序从便宜、确定的开始。先校验必填字段、身份、权限、数值和版本，再做语义核查；高风险和证据冲突才进入人工。验证失败应返回具体失败项，不要只给一个总分。"通过"表示该检查项满足当前版本的成功标准；"退回"表示产物回到修改队列并必须重新验证；"转人工"表示系统不能凭现有证据决定；"系统错误"表示验证器本身没有完成检查。放行条件还要写清必过项、允许的例外、证据有效期和重新验证触发条件。

**验证结果记录**

下面是不可执行的 JSON 记录示例，只用于说明验证结果如何绑定任务、产物、证据和有效期；字段名和状态值需按实际系统的模式定义（Schema）调整。

```json
{
  "task_id": "task-391",
  "artifact_version": "draft-v4",
  "verification_policy": "customer-reply-v6",
  "result": "needs_human",
  "checks": [
    {"id": "recipient", "status": "pass", "evidence": "contact-72/v9"},
    {"id": "promise", "status": "fail", "reason": "交付日期正在复核"}
  ],
  "required_role": "account_owner",
  "expires_at": "2026-08-15T12:00:00+10:00"
}
```

验证记录绑定产物版本。草稿、收件人或权威事实变化后，旧结果不能继续放行。
