# A.18 组织循环目录条目

> 原附录 A A.18 节，与原第 15 章 15.7 节"建立组织级循环目录"的十类治理信息合并为一份（2026-11）；文中章号已按新版调整。目录字段在第 9 章 9.2 节正文中使用精简版，这里保留完整版。

每条目录对应一条有独立责任和边界的循环。顺着业务任务查消费者，再把数据域、服务身份和外部动作对应起来，核对实际权限是否超出登记范围；上下游合同则帮助确定暂停或退役时要通知谁。评审发现责任空缺、证据过期或人工容量不足时，应把缺口交给相应负责人，未解决前不扩大运行范围。

```text
循环名称 / ID / 状态：试验 / 生产 / 暂停 / 退役
业务、方法、系统、风险负责人：
运行值班与替班：
业务任务和消费者：
自动化权限阶段：
数据域、用途、地区、保留：
模型、供应商、工具和运行形态（按会话寿命、数据位置、调度入口和权限记录）：
服务身份、权限与临时授权：
外部动作和最大影响（金额、对象数、数据范围或时限）：
验证、人工门禁与审批容量：
上下游循环和连接合同（事件、状态或动作接口的业务约定）：
预算、队列、告警和暂停入口：
最近评测、演练、事故和复核：
人工退路：
数据与状态导出：
退役条件和预定复核日期：
```

上述字段覆盖组织目录应记录的十类治理信息：负责人及其可决定、批准和复核的范围；模型、供应商、数据域和部署区域（版本变更或数据事故时可回查）；任务、规则、Skill 和评测版本（变更或事故后可重现当时结果）；所有外部动作与每次动作的上限和停止条件；人工审批角色与按风险等级的处理容量；当前自动化权限阶段与灰度范围；安全、隐私和合规评审日期及逾期动作；监控、事故和恢复手册；上下游依赖与下游消费者（变更或退役时可通知）；最近一次使用和预定退役日期（找出无人使用的循环并安排退役复核）。

目录不是资产展示页。没有消费者、无人维护、权限过宽或无法停止的循环，要在目录中暴露出来。若字段出现 Webhook（事件发生时向指定端点推送通知）或 MCP（连接 Agent 与外部工具、资源的协议），还要记录授权仍由具体服务控制，不能把协议名称当成业务许可。

**影子自动化**

没有登记、却已在生产环境读取数据或执行动作的自动化，属于"影子自动化"。组织可以允许受控实验，但只要循环开始读取敏感数据、代表组织执行对外操作，或影响正式业务状态，就要登记到目录中，接受相应管理。

**字段门禁**

目录记录只有通过字段门禁检查，才能标为"生产中"。业务或风险负责人缺失、已经离岗或无法确认时，先暂停循环的外部动作，并指定替代负责人；模型、规则、Skill 或评测版本缺失时，保持当前已批准的版本，不得继续灰度；数据域、部署区域、动作范围或审批角色缺失时，只允许使用合成数据生成草稿；评审已过期、恢复手册不可用或依赖关系无法核对时，停止扩大权限，并安排复评。若距最近一次使用的时间已超过退役阈值，相应循环就进入待退役队列，由业务负责人确认消费者、在途任务和数据保留义务后再关闭。发生安全事故、供应商变更或人员交接时，应能通过目录查清影响范围，不能填完审批表后就再也不用它。

**从现有工具起步**

建立目录时，可以先用现有的资产管理工具起步，专用 Agent 平台属于后续选项。小团队可以在带字段类型、唯一 ID 和权限视图的多维表格或关系数据库中建立目录；已经使用 Backstage、ServiceNow 配置管理数据库（Configuration Management Database，CMDB）等服务目录的组织，可以先验证这些工具能否增加循环类型、数据域、动作范围、负责人和最近运行时间字段，再决定是否采用。官方资料入口见[来源说明](../../sources/来源说明与参考资料.md)中的 `SRC-PLAT-003`，不承诺任一版本默认具备这些字段或同步能力。目录只保存元数据与证据链接，不复制密钥、客户原文或完整运行日志。目录工具便于查找循环及相关记录，权限引擎、评测系统和事故处理流程仍需各自独立建设。建表时可以直接采用上面列出的字段集合，并为每条记录补上循环标识、记录人和最近更新时间。
