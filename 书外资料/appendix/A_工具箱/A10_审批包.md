# A.10 审批包

> 原附录 A A.10 节外移；文中章号已按新版调整。

审批包用于让批准人判断一个具体动作是否可以发生。先并列已确认事实与未决事项，再把拟执行动作、最大影响和版本差异对应起来；每个可选决定都要连到后续状态，避免"延后"以后仍自动执行。证据不足时应选择补资料、延后或转交，不能把空白事项解释为没有风险。

```text
为什么需要你决定：
业务对象与当前状态：
拟执行动作和最大影响：
已经确认的事实及来源：
仍不确定或冲突的事项：
与上一版本的差异：
验证失败或警告：
可选决定：批准 / 修改 / 拒绝 / 延后 / 转交
每项决定的后续状态：
决定截止和超时策略：
审批作用范围和失效条件：
```

审批界面优先展示差异、失败和即将发生的动作。不要用一页模型摘要隐藏原始证据。具名批准还要校验角色、对象、金额和有效期。
