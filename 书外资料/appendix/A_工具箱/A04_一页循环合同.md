# A.4 一页循环合同

> 原附录 A A.4 节外移；文中章号已按新版调整。

循环合同规定系统承担什么，不是写给模型看的长提示词。填写时把"处理范围"写成可识别的业务对象和任务类型，把"明确不处理"写成触发条件与转交角色；"发现"描述何时创建任务，"交付"描述允许读取和执行的边界，"验证"描述放行证据，"记忆"描述跨运行保存什么，"调度"描述何时推进或停止。

```text
循环名称 / 版本：
业务目标：
服务对象和结果消费者：
处理范围：
明确不处理：

发现
- 创建任务的信号：
- 稳定任务身份：
- 重复、乱序和补漏：

交付
- 权威输入与版本：
- 最小上下文：
- 允许的工具、数据和权限：
- 时间、调用和费用预算：

验证
- 确定性检查：
- 语义或领域检查：
- 人工门禁：
- 严重失败条件：

记忆
- 保存的状态、事实和证据：
- 反馈怎样成为规则候选：
- 过期、删除和更正：

调度
- 事件、周期和截止：
- 重试、退避和无进展停止：
- 背压、暂停和恢复：

外部副作用：
最大批量 / 金额 / 影响范围：
人工退路：
业务 / 方法 / 系统 / 风险负责人：
上线证据与下次复核日期：
```

合同中的"明确不处理"很重要。例如邮件循环可以起草常规进度回复，但不处理合同承诺、投诉赔偿和身份无法确认的来信。遇到范围外任务时，系统返回清楚状态和所需责任人，不用宽泛提示词硬做。
