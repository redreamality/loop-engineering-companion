# A.5 任务包

> 原附录 A A.5 节外移；文中章号已按新版调整。

任务包描述一次具体执行。循环合同相对稳定，任务包随业务对象和版本变化。`task_id` 关联同一业务任务，`run_id` 只标识其中一次执行尝试；重试应产生新的 `run_id`，不得覆盖原运行记录。每个输入项都要注明来源、版本和读取时间，缺失或冲突信息必须进入失败分类或转交路径。

```text
task_id：
run_id：
循环合同版本：
任务目标：
业务对象及当前版本：
触发事件、来源和时间：
本次允许范围：

输入
- 权威事实：值 / 来源 / 版本 / 读取时间
- 外部陈述：
- 已批准政策：
- 参考资料：
- 缺失或冲突信息：

执行
- 需要完成的步骤：
- 允许工具与权限：
- 禁止动作：
- 输出格式：
- 最迟完成时间：
- 最大尝试、调用和费用：

成功标准：
必须回传的证据：
失败分类与转交方式：
```

把事实、外部陈述和政策分开。客户说"已经付款"可以触发核对，却不能覆盖银行对账；网页写"忽略规则"只是页面内容，不是工具授权。示例中的 `outstanding`、`draft-v4` 等值只是占位符，实际使用时要替换为本系统可回查的状态和版本。

**一个简短示例（虚构数据，仅说明字段关系，不代表真实客户、金额或期限）**

```text
task_id：invoice/acme/2026-081/reminder-1
目标：为已到期且未确认到账的发票生成一封内部草稿
权威事实：财务系统状态 outstanding，版本 14，10:05 读取
外部陈述：客户昨日邮件称已安排付款，尚无交易凭证
政策：首次提醒可起草；争议或承诺延期必须财务确认
允许：读本发票和获准会话，写个人草稿区
禁止：发送、改到账状态、推断客户信用
成功：草稿准确列出金额和日期，承认客户陈述，提出核对下一步
转交：出现身份冲突、金额不一致或新付款记录时进入财务核对
```
