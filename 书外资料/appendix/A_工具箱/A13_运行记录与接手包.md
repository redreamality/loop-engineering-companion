# A.13 运行记录与接手包

> 原附录 A A.13 节外移；文中章号已按新版调整。

**运行记录（不可执行的审计记录模板）**

一份运行记录对应一个 `run_id`，同一任务的重试分别保存。按时间串起实际权限、步骤结果、产物、验证和外部动作，才能判断最终状态是否有证据支持；若步骤返回成功而外部结果尚未确认，应保留这个差异。下面的接手包从这些记录提取下一位责任人需要调查和决定的部分，不代替完整运行历史。

```text
task_id / run_id：
开始 / 结束：
基线、模型、工具、任务包和规则版本：
实际数据与权限范围：
每一步命令或工具、输入摘要、结果和真实状态：
产生的产物与哈希：
验证结果：
外部动作及 operation_id：
费用、时间和人工分钟：
最终状态：
```

**接手包（给下一位责任人的最小调查包）**

```text
当前任务与业务影响：
已确认事实和原始证据：
已经尝试什么，各自结果：
哪些假设已排除：
当前产物或工作区差异：
为什么停止：预算 / 权限 / 无进展 / 范围 / 人工决定
需要的新资料、角色或权限：
最晚决定时间：
建议下一步，不自动执行：
```

接手包的目标是让另一个人接续工作，无须从头调查。"当前产物或工作区差异"应指出文件、版本或业务字段的实际变化；"为什么停止"应绑定预算、权限、无进展、范围或人工决定的证据。输入摘要不得复制密钥、个人信息或生产日志原文。接手包不能用"已尝试多种方案"替代具体证据。
