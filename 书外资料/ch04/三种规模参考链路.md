# 三种规模参考链路

> 配套《循环工程》第 4 章 4.11 节“三种规模的设施组合”。候选组件见正文表 4-4；正式采用前，用第 4 章 4.10 节的七项证据在自己的账户、连接器和部署方式上逐项演示。

## 个人低风险循环

场景：每周生成个人项目摘要，不对外发送。

```text
日历提醒 → 自动化平台工作流 → 指定项目只读连接
→ Agent 生成结构化草稿 → 表格规则检查 → 个人确认
→ 任务表记录结果与修改
```

重点是明确数据范围、草稿位置、任务标识，以及出错后如何改由人工处理。队列可以是一张表，审批人就是本人，没有必要部署多租户服务。

## 团队日常循环

场景：每天处理数百封客户邮件，回复需审批。

```text
邮件事件 + 补偿扫描 → 任务队列与租约 → 工作流编排
→ 按会话签发权限 → 分类 / 起草 → 规则和语义验证
→ 团队审批队列 → 统一发送服务 → 业务与审计台账
```

这一档需要处理并发、人工处理能力、业务幂等、值守安排和多用户权限等问题。普通自动化平台仍可承担编排，但客户身份和发送门禁应由正式系统管理。

## 组织高风险循环

场景：发票核对与付款建议，跨部门审批。

```text
数据锁定事件 → 多租户任务控制面 → 隔离执行环境
→ 确定性财务校验 + Agent 异常解释 → 双人审批
→ 专用付款动作服务 → 对账确认 → 事件与合规审计
```

这里要配置服务身份（与个人账号分离、供循环长期读写的专用身份），做到职责分离，并设置金额与批量上限。还要明确如何处理状态未知、执行补偿、进行灾难恢复，以及应对组织变更。Agent 只负责其中适合理解和解释内容的少数步骤。

## 三档共同的提醒

从个人到组织，变化的是责任，而不只是人数：设施组合不能只按员工人数选择，一个人发起的高金额付款也需要高风险控制，一家大公司的内部草稿循环则可以采用简单配置。选定与当前任务匹配的一档后，先搭出一条最小路径，再故意制造重复信号、权限拒绝和动作超时，确认工具真正承担了表中写下的责任。
