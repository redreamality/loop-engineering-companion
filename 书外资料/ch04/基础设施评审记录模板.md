# 基础设施评审记录模板

> 配套《循环工程》第 4 章 4.10 节“组件边界与选型证据”。

完成选型演示和故障演练后，可以把结论整理成一份基础设施评审记录。下面是填写模板，不是可以直接运行的代码：

```text
循环与业务任务：
预计任务量与峰值：
最大外部副作用：

信号接入：组件 / 身份 / 游标 / 补漏方式
任务状态：组件 / 状态表 / 并发与租约
编排调度：分支 / 重试 / 背压 / 暂停
执行环境：沙箱 / 权限 / 凭证 / 资源上限
验证审批：规则 / 证据 / 人员 / 容量
记忆观测：事实 / 日志 / 指标 / 保留与删除

人工承担的接口：
已演练故障：
当前缺口与接受理由：
何种证据出现时升级组件：
```

这份记录可以很短，但要让团队看清楚：尚未实现的功能目前由谁手工完成，哪些事情还没有人负责，以及什么时候需要更换组件。
